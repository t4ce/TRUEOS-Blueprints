Spirit label load probe

Build from the TRUEOS-Blueprints checkout with publishing disabled:
  bash probes/spirit_labels/build.sh

Output:
  TRUEOS-Blueprints/dist/spirit-labels-probe.bp

For a local run, place the archive at apps/common/spirit-labels-probe.bp on
TRUEOSFS. An existing Blueprint can launch it through the SDK:

  trueos::vshell::launch_with_destination(
      "common/spirit-labels-probe.bp",
      "",
      trueos::vshell::LaunchDestination::NewShell3,
  )?;

For a Shell3 CMD launch, a Blueprint can instead import it by writing
common/spirit-labels-probe.bp to vFile:appdb-install. Then run spirit-labels-probe
from CMD.

The probe uses the production snapshot publisher and runs two concurrent-label
loads in one process:

  running-10   Probe 01 through Probe 10, for 26 seconds
  running-16   Probe 01 through Probe 16, for 26 seconds
  approval-16  All 16 should stop and show blue status, for 3 seconds
  completed-16 All 16 should retain their last motif and show green status
  disconnect   Removes this probe's labels before the process exits

During each running stage, check that all numbered labels stay visible and
move around Lilly as their motifs advance every second. Each running
hold covers one full nominal 24-second orbit.
The console prints one line with the stage, count, hold duration, revision and
native return code at the beginning of each hold. A successful publication run
has rc=0 at every stage and ends with accepted=true cleaned=true. Publication
alone does not confirm the labels appeared or moved on the display.

The probe performs no model, network or input activity. A live Codex producer
owns a separate set of markers. Place Lilly away from the display edges and
close other active agent runs when measuring the exact counts from this probe.
