XERJ native integration smoke probe

Build from the TRUEOS-Blueprints repository:
    cargo bp probes/xerj_smoke

Run xerj-smoke through Shell3 on TRUEOS after installing xerj.bp, codex.bp and
xerj-smoke.bp in the regular AppDB. Optional launcher arguments:
    xerj-smoke [xerj.bp|/absolute/path/xerj.bp] [existing-state-parent] [codex.bp|/absolute/path/codex.bp]

Shell3 accepts the bare app name; supplying arguments requires a parent using
the existing child_hull::spawn_program API. The bare name runs the full check.

The default program is xerj.bp. The default state parent is the current
TRUEOSFS directory. Each run creates its own xerj-smoke-<epoch-nanos> directory,
retains it for inspection, and reserves three unused consecutive loopback ports.
Engine state lives separately under /apps/xerj/smoke/<same-run-basename>. The
kernel grants the XERJ archive its own private root before entry; only the
engine creates and reads its data. The probe inspects it through HTTP/MCP,
without receiving XERJ's access key. This requires the native XERJ storage policy.
It never reuses another run's data directory, indexes, namespaces, or listeners.

Checks:
  * Launch the full engine in a fresh child Hull, without external services.
  * Readiness on the ES-compatible and native REST listeners.
  * Write one tiny Rust source, one Markdown file, and an embedded real SQLite
    database under this run's corpus; autoindex state is a sibling directory.
    The SQLite fixture has one calibrations row (id 37), no journal or WAL, and
    exercises the engine's actual bundled SQLite provider during autoindex.
  * Separate CLI children: autoindex --dry-run --json, then autoindex --json
    against the existing node, using this run's own fixed-prefix namespace.
    Require all three planned files, a complete zero-junk three-file result, a
    matching journal finish record, a visible catalog run, and exact searchable
    records from each file, including the SQLite table name and row locator.
  * HTTP index/write/search and lexical agent-memory store/recall.
  * Tonic unary /xerj.v1.XerjSearch/Health on the gRPC listener, with a complete
    successful gRPC response and positive index/document counts, after HTTP
    indexing and again after restart. Uses matching Tonic 0.12.3 / Prost 0.13
    wire types on a current-thread runtime, with a 20-second total deadline.
  * Separate MCP child: initialize, initialized notification, tools/list,
    xerj_search, xerj_memory_store, and xerj_memory_recall. Prefix code search
    must return the generated Rust AST definition with its exact source line.
  * Actual native Codex child, using `app-server --listen stdio://`: create a
    fresh CODEX_HOME under this run's directory, register direct XERJ stdio MCP
    against this run's existing engine, initialize the public app-server API,
    start an ephemeral thread, discover XERJ tools and call xerj_search and
    xerj_memory_recall through Codex. Require the exact document, AST definition
    and source line, the exact SQLite row, and both existing memory records.
    Confirm app-server reports
    the same std platform value as the native probe and this run's CODEX_HOME.
    The current native std reports an empty platformOs; native target identity
    comes from this probe's target guard and the kernel's admitted Blueprint.
    Save codex-mcp-evidence.json
    containing only this synthetic test's server metadata and retrieval results.
    While that Codex remains active, require a second Codex launch to reject
    synchronously with ERR_UNAVAILABLE; run the retrieval checks on the first
    instance after rejection. After its complete shutdown, relaunch Codex,
    initialize its app-server again, then stop it. Requires the kernel's shared
    one-Codex admission guard; run with no other Codex VM active.
    The child exit marker precedes the final carrier drain, so relaunch retries
    only ERR_UNAVAILABLE for at most 90 seconds while admission remains held.
    Before relaunch, remove the fixture's MCP override. The second process must
    discover direct XERJ through the native packaged defaults, activate or reuse
    the normal authenticated xerj-service via --ensure-local, and call read-only
    xerj_status through Codex. Save only projected health facts and tool names
    in codex-default-mcp-evidence.json. Leave that independent service running.
  * Flush acknowledged writes, terminate owned children, restart the same
    engine/data directory, and retrieve the document, corpus files and both
    memory records.
  * Stop every owned child on success or error, including the random-port
    fixture engine. The independent normal XERJ service remains running.

Fixture XERJ launches use --disable-feedback; XERJ processes also receive
XERJ_DISABLE_FEEDBACK=true. The engine
uses lexical embedding. Neural model download, external model services, TLS,
remote network access, larger corpora, and field reports are outside this check.
The gRPC check covers unary health and HTTP/2 transport, not gRPC document
mutation, search, streaming, authentication, or TLS.

The default openssl-check feature checks the native OpenSSL provider used by
production WebAuthn. Before engine startup, it exercises hardware entropy,
SHA-256, P-256 signatures, tamper rejection and a fixed ASN.1 time on the entry
thread and two workers. Native packaging must pass the ordinary retired-import
and CABI guards. Passing host crypto checks alone establishes no native runtime
result; the live probe must emit crypto_native and its final success marker.

The Codex phase uses an isolated provider that requires no credentials and sends
no model turn. It disables plugins and shell snapshots. It reads no live Codex
configuration or credentials. The first phase uses an explicit synthetic auth
header against its own insecure engine, preventing local credential discovery.
The subsequent packaged-default phase intentionally uses the normal XERJ
service and resolves that service's key inside the MCP process; key material is
never returned to the probe. This verifies native Codex's real MCP runtime
and retrieval; it does not claim a model chose the tools or returned an answer.
The normal private SQLite service may be reused; CODEX_SQLITE_HOME points at the
fresh run directory, and its complete database paths select separate database
names. No live Codex database is queried by the probe.
Codex stages are codex_initialize, codex_second_rejected, codex_mcp_tools,
codex_mcp_search, codex_mcp_code_fixture, codex_mcp_sqlite_fixture,
codex_mcp_memory, codex_stopped,
codex_default_mcp_tools, codex_default_service_ready, codex_relaunch and
codex_default_service_retained.

Evidence is stdout and structured IMPORTANT stage markers under xerj-smoke:
xerj-smoke v=1 stage=<name> ok=true. The final marker is
stage=end ok=true only after persisted reads and child cleanup pass. Its
evidence_root field identifies the probe-owned directory separately from private
engine data. On failure,
stage=end ok=false includes a JSON-escaped error; unexpected child exits include
the bounded stdout tail. Readiness is limited to 90 seconds per listener,
requests to 20 seconds, Codex app-server requests to 150 seconds, and child
termination to 20 seconds. Polls drain child
stdout so a full output queue cannot prevent engine or MCP progress.
The finite gRPC call drains engine stdout before and after its current-thread
runtime; all child Hull control remains on the synchronous entry thread.
Each autoindex CLI child has a 120-second deadline and a 2 MiB stdout limit.
The native child ABI exposes stdout and lifecycle status, without stderr or
process exit codes. Autoindex prints xerj-done on stderr, so this probe does not
claim to observe that completion marker. It requires an exited child, the
genuine --json result and journal/catalog/retrieval evidence listed above;
it does not infer success from child exit alone. The three-file fixture must be
fully indexed without junk, missing datasets or skipped inputs.

Host validation (does not launch XERJ or pretend to exercise the kernel ABI):
    cargo test --manifest-path probes/xerj_smoke/Cargo.toml
